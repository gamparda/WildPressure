# WildPressure

Paper 26.2 build 87에서 자연 야생 스폰을 대체하고, 실제 몹 개체군과 플레이어 반응형 야생 작전을 직접 관리하는 플러그인입니다.

## 요구 사항

- Paper `26.2 build 87`
- Java 25

## v0.2.0 기능

### 실제 개체군

- `NATURAL`, `CHUNK_GEN` 스폰 선택 차단
- 단독 플레이어 영향권당 실제 관리 몹 약 5,000마리
- 가까운 플레이어끼리 생태 구역을 공유해 예산 중복 방지
- 청크 이벤트와 분산 갱신 기반 엔티티 인덱스
- 지역 고갈, 재생성 대기, 외곽 보충
- MSPT 임계치 이상 신규 생성 정지

### 압력과 흔적

다음 행동이 생태 구역의 야생 압력을 높입니다.

- 블록 파괴·설치
- 문 사용
- 폭발
- 플레이어가 받은 피해
- 관리 몹의 시체
- 밝은 플레이어 거점의 저빈도 광원 표본
- 소음 미끼

압력은 시간에 따라 감소하며 임계치에 도달한 구역에서만 작전이 시작됩니다.

### 콘텐츠 AI

작전은 다음 단계로 진행됩니다.

1. **SCOUTING** — 실제 관리 몹 한 마리가 자극 위치를 조사합니다.
2. **MOBILIZING** — 정찰 성공 후 인접 생태 구역의 실제 몹이 집결합니다.
3. **ASSAULT** — 제한된 경로 요청 예산 안에서 플레이어를 획득하고 종별 역할로 공격합니다.
4. **RETREAT** — 지속 시간 또는 생존 비율 조건에 도달하면 목표를 해제하고 흩어집니다.

종별 기본 역할:

- 좀비 등: 정면 압박
- 스켈레톤·스트레이·보그드: 원거리 역할
- 거미·동굴거미: 측면 목적지
- 크리퍼: 돌파 역할

`ai.siege.enabled`를 켜면 설정에 명시된 블록만 여러 번 공격한 뒤 파괴할 수 있습니다. 기본값은 안전을 위해 `false`입니다.

### 소음 미끼와 보상

- `/wild lure [player]`로 소음 미끼 지급
- 우클릭 위치에 강한 압력과 유인 목표 생성
- 작전에 편입된 몹을 죽인 플레이어의 기여도 추적
- 작전 종료 시 경험치와 설정된 묶음 보상을 인벤토리로 직접 정산

## 명령어

- `/wild status` — 개체군·활성 작전·MSPT
- `/wild inspect` — 현재 구역 개체 수와 압력
- `/wild operations` — 작전 단계·생존 수·처치 수
- `/wild profiler` — 개체군/AI 실행 시간, 경로 요청, 돌파 상태
- `/wild lure [player]` — 소음 미끼 지급
- `/wild reload` — 설정 재적용

권한: `wildpressure.admin` (기본 OP)

## 설치

1. 릴리스의 `WildPressure-0.2.0.jar`를 `plugins/`에 넣습니다.
2. 서버를 시작합니다.
3. 기존 v0.1.0 사용자는 새 JAR으로 교체한 뒤, 새 `config.yml`을 참고해 `pressure`, `lure`, `ai` 항목을 추가하십시오. 누락된 항목은 코드 기본값으로 동작합니다.
4. `/wild profiler`로 재조정 및 AI 비용을 확인합니다.

## 빌드

```bash
mvn clean verify
```

결과물: `target/WildPressure-0.2.0.jar`

## 성능 원칙

- 모든 AI 작업은 서버 메인 스레드에서 Bukkit API를 안전하게 사용합니다.
- 전체 개체 목록 검사는 활성화 시 기존 몹 편입을 위한 1회만 수행합니다.
- 작전 집결은 개체 인덱스를 한 번만 순회합니다.
- 경로 요청은 작전별·주기별 예산으로 제한합니다.
- 몹마다 스케줄러나 파일 저장을 만들지 않습니다.

## 운영 주의

실제 엔티티 5,000마리는 큰 부하를 유발할 수 있습니다. 최초 시험은 `target-per-player`, `max-spawns-per-pass`, `max-active-operations`, `max-group-size`, `max-path-requests-per-operation-pass`를 낮춘 상태에서 시작하십시오.

구조물 돌파는 월드를 실제 변경하므로 허용 목록과 보호 정책을 검토한 뒤 켜야 합니다. 현재 버전에는 WorldGuard 연동이 없으므로 보호구역을 사용하는 서버에서는 `ai.siege.enabled: false`를 유지하는 것이 안전합니다.
